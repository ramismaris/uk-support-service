# План реализации

Порядок работ, без сроков. Этот файл — трекер: пункт отмечается `[x]` в том же коммите, где он сделан.

## Как устроен план

- Два трека: бэкенд (Б) и фронтенд (Ф).
- Бэк-этап закрывается без фронта: интеграционные тесты, Swagger (`/docs` в dev), бот в Max.
- Фронт берёт этап, когда нужный бэк-этап закрыт, и работает с настоящим API. Фронт идёт позади и догоняет; на бэкенд это не влияет.
- Бэкенд фронтендер поднимает у себя одной командой — без бота и с демо-данными.
- Доработки API, которые просит фронт по уже закрытым этапам, бэкенд берёт в первую очередь.
- Совместных шагов два: общий старт и демо.

## Общий старт

- [ ] Домен и Caddy: `/api` → бэкенд, остальное → статика фронта; регистрация мини-приложения на домен. Делает бэкенд-разработчик.
- [ ] Отдельный тестовый бот у каждого разработчика: два процесса на polling с одним токеном делят апдейты между собой.
- [ ] Сценарий демо на 3 минуты — `docs/demo.md`.
