🏗 Архитектура системы

Пользовательская часть размещается внутри мессенджера Макс (бот)

Часть управления вынесена в мини-приложение Макса

Веб-панель — отдельная версия для управления (решили делать)

👥 Роли

Три роли: клиент, админ, менеджер

📋 Заявки и коммуникация

Заявки оформляются в виде тикетов

Общение с клиентом ведётся внутри тикета (чат по заявке)

Переписка с мессенджером — нужна интеграция

⚙️ CMS / Управление контентом

Частичная CMS для заполнения контента: стартовое сообщение, стилизация, панель

Возможность менять стартовое/приветственное сообщение

В приветственном сообщении обязательна фотография

Возможность просмотра работ (портфолио/примеры)

🎨 UI/UX

Поддержка светлой и тёмной темы (обсуждалось как желаемое)

Использование UI-кита Макса (стилизованные кнопки)

Кастомная анимация ожидания одобрения заявки (по аналогии с курьером в Яндексе — визуальный индикатор статуса)

🤖 ML / Авто-фильтрация

Интеграция ML-компонента для фильтрации входящих заявок

Автоматическая классификация вопросов — чтобы нерелевантные обращения не доходили до менеджеров

🔗 Данные и интеграции

Автоматическое определение клиента по данным (лицевой счёт / профиль) — чтобы клиент не заполнял вручную адрес, квартиру и т.д.

Два возможных пути интеграции данных: с подключением к базе управляющей компании и без (core-режим с ручным заполнением)

Возможность будущей интеграции с CRM

📦 Модель распространения

Коробочная схема — клиент покупает готовый продукт и самостоятельно настраивает

Подряд — команда сама всё настраивает под клиента
